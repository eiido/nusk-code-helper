# مساعد أكواد نسك | Nusuk Code Helper

أداة مجتمعية مجانية باللغة العربية لتصفّح الأكواد ونسخها، وحفظ التقدم، ومشاركة أكواد جديدة، مع دليل استخدام وروابط المنصة الرسمية. صُمّمت الواجهة للموبايل أولًا، وتُدار الأكواد والمحتوى من لوحة إدارة دون إعادة نشر الموقع عند كل تعديل.

**[افتح الموقع](https://nusk-code-helper.vercel.app/)** · [سجل المصادر والتحقق](RESEARCH.md) · [ملاحظات الاختبار](QA.md)

> مشروع مستقل غير تابع لمنصة نسك أو وزارة الحج والعمرة. لا يتحقق الموقع من قبول الأكواد داخل نسك، ولا يضمن فرصًا إضافية أو الفوز. المرجع لشروط المشاركة والجوائز هو المنصة الرسمية؛ متابعة النسخ والاستخدام هنا ليست عدّادًا لفرص السحب.

## المميزات

### للزائر

- واجهة عربية باتجاه RTL، مع تبويبات للرئيسية والأكواد والدليل والمسابقة ومشاركة كود.
- بحث ونسخ الأكواد، وتحديد حالة كل كود: منسوخ، مستخدم، متخطّى، أو لم يعمل.
- حفظ التقدم محليًا دون إنشاء حساب، مع تصدير نسخة احتياطية واستيرادها والتراجع عن التغييرات.
- مشاركة كود والإبلاغ عن كود لا يعمل.
- دليل يدعم الصور والفيديو، وروابط نسك وتحميل التطبيق، ومعلومات موضح معها المصدر ووقت التحقق.
- مراجعة تحديثات الأكواد والمحتوى كل ٤٥ ثانية أثناء ظهور الصفحة، وعند العودة إليها.

### للإدارة

- نظرة عامة بإحصائيات فعلية، وتنقل مناسب للموبايل والديسكتوب.
- البحث في الأكواد وإضافتها وتعديلها ونشرها ورفضها، مع حذف قابل للاستعادة.
- مراجعة البلاغات وإغلاقها، أو حذف الكود وإغلاق بلاغاته معًا.
- تحكم في استقبال الإضافات والنشر التلقائي؛ النشر التلقائي مفعّل افتراضيًا للإضافات الجديدة.
- تعديل الهوية والنصوص والروابط والمسابقة والتحديثات والدليل والأسئلة الشائعة.
- حفظ صريح للإعدادات، وتنبيه للتغييرات غير المحفوظة، وحماية من الكتابة فوق تعديل أحدث من جلسة أخرى.

## التقنيات وبنية البيانات

| الجزء | التقنية |
| --- | --- |
| التطبيق وواجهات API | Next.js 16، React 19، TypeScript |
| قاعدة البيانات والمصادقة | Supabase Postgres وSupabase Auth |
| التصميم | CSS، خط Alexandria، وأيقونات SVG |
| الاستضافة المستخدمة | Vercel |
| الاختبارات | Node.js Test Runner، jsdom، esbuild |

قاعدة البيانات هي مصدر الأكواد المنشورة والمحتوى. تمر طلبات الكتابة عبر السيرفر، وتتطلب عمليات الإدارة جلسة صالحة وبريدًا ضمن قائمة المديرين. لا تتاح الجداول مباشرة للزائر. تبقى متابعة الزائر في `localStorage` على جهازه؛ نقلها لجهاز أو نطاق آخر يحتاج تصديرًا واستيرادًا.

## التشغيل محليًا

المتطلبات: **Node.js 24.15 أو أحدث من سلسلة 24**، وnpm، ومشروع Supabase. هذه النسخة من Node متوافقة مع أدوات الاختبار المرفقة.

```bash
git clone https://github.com/eiido/nusk-code-helper.git
cd nusk-code-helper
npm ci
cp .env.example .env.local
```

أكمل إعداد Supabase والمتغيرات التالية، ثم شغّل:

```bash
npm run dev
```

- الموقع: `http://127.0.0.1:3000`
- الإدارة: `http://127.0.0.1:3000/admin`

### إعداد Supabase

1. أنشئ مشروع Supabase جديدًا، ثم نفّذ محتوى [supabase/schema.sql](supabase/schema.sql) في SQL Editor. ينشئ الجداول والدوال والإعدادات، ويستورد ١٢١٦ كودًا من البيانات الأصلية دون التحقق من صلاحيتها داخل نسك.
2. أنشئ مستخدم إدارة ببريد مؤكد من Supabase Auth. أبقِ تسجيل الدخول بالبريد مفعّلًا، وعطّل التسجيل العام إذا كان المشروع مخصصًا لهذه الأداة.
3. انسخ القيم المطلوبة إلى `.env.local`، وأضف بريد المدير إلى `ADMIN_EMAILS`.
4. أعد تشغيل خادم التطوير بعد تعديل متغيرات البيئة، ثم سجّل الدخول من `/admin`.

**لترقية تثبيت قديم فقط:** نفّذ [ترقية الإدارة الديناميكية](supabase/migrations/20261105_dynamic_admin.sql). الترقية تحافظ على الإعدادات والحالات السابقة ولا تعيد نشر الأكواد المحذوفة أو المرفوضة. لا تحتاجها منفصلة بعد تنفيذ مخطط التثبيت الجديد الكامل.

### متغيرات البيئة

استخدم [.env.example](.env.example) كقالب؛ جميع القيم فيه فارغة عمدًا.

| المتغير | الاستخدام | النطاق |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | رابط مشروع Supabase | عام |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | مفتاح Supabase القابل للنشر | عام |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح السيرفر؛ يقبل Secret Key الجديد أو service_role القديم | سري، للسيرفر فقط |
| `ADMIN_EMAILS` | عناوين المديرين المسموح لهم، مفصولة بفواصل | للسيرفر فقط |
| `RATE_LIMIT_SECRET` | قيمة عشوائية بطول ٣٢ حرفًا أو أكثر لحماية معرّفات حدود الطلبات | سري، للسيرفر فقط |
| `NEXT_PUBLIC_SITE_URL` | رابط الموقع الكامل للروابط الوصفية؛ محليًا `http://127.0.0.1:3000` | عام |

لتوليد قيمة عشوائية لـ`RATE_LIMIT_SECRET` على جهازك:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

لا ترفع `.env.local` أو النسخ الاحتياطية المحلية إلى GitHub. لا تضف بادئة `NEXT_PUBLIC_` لأي مفتاح سري. المستودع يستبعد ملفات البيئة الفعلية و`.local-backups/` عبر `.gitignore`.

## النشر على Vercel

1. استورد مستودع GitHub، واختر **Next.js**. اجعل Root Directory هو المجلد الذي يحتوي `package.json`، واترك أوامر البناء والتثبيت ومجلد الإخراج على الإعدادات الافتراضية.
2. أضف متغيرات البيئة المطلوبة إلى بيئة **Production**. اجعل `SUPABASE_SERVICE_ROLE_KEY` و`RATE_LIMIT_SECRET` من نوع **Secret / Sensitive** عند توفر الخيار.
3. اضبط `NEXT_PUBLIC_SITE_URL` على رابط نشر نسختك؛ رابط النسخة الحالية هو `https://nusk-code-helper.vercel.app`.
4. انشر المشروع. إذا عرفت الرابط النهائي بعد أول نشر، حدّث المتغير ثم أعد النشر.
5. افتح `/admin` وتحقق من تسجيل الدخول وظهور البيانات.

تغييرات الكود أو التصميم ومتغيرات البيئة تحتاج نشرًا جديدًا. تعديل الأكواد والمحتوى من لوحة الإدارة يُحفظ في Supabase ويصل للزوار دون بناء نسخة جديدة. أي بيئة Preview مرتبطة بنفس مشروع Supabase ستشارك بياناته؛ استخدم مشروعًا منفصلًا إذا أردت اختبار تعديلات دون التأثير على البيانات الحية.

## الأوامر والفحص

| الأمر | الوظيفة |
| --- | --- |
| `npm run dev` | تشغيل التطوير محليًا |
| `npm run build` | بناء الإنتاج |
| `npm start` | تشغيل البناء محليًا |
| `npm run typecheck` | فحص TypeScript |
| `npm test` | اختبارات المنطق والمكونات |
| `npm run smoke` | فحص API مع خادم محلي يعمل؛ لا ينشئ صفوف اختبار |
| `npm run preview:html` | إنشاء لقطة HTML مستقلة للواجهة العامة في المجلد الأب |
| `npm run preview:admin` | إنشاء معاينة HTML للإدارة ببيانات توضيحية محلية فقط |

معاينة الإدارة لا تتصل بقاعدة بيانات ولا تحتاج بيانات دخول حقيقية. معاينة الواجهة العامة تستخدم الأكواد والمحتوى المنشور وقت التوليد عند تهيئة Supabase؛ ليست نسخة حية.

الاختبار المتصل `node scripts/check-dynamic-data.mjs` مخصص **لقاعدة تطوير منفصلة**: يغيّر سياسة النشر مؤقتًا، ويضيف صفوف اختبار ثم ينظفها. لا تشغّله على قاعدة تستقبل مستخدمين فعليين. تفاصيل الفحوص وحدود المراجعة البصرية في [QA.md](QA.md).

## تنظيم المشروع

```text
app/                    الصفحات وواجهات API
components/             واجهة الزائر والإدارة ومحرر الإعدادات

tests/                  الاختبارات
```

## المحتوى والخصوصية وحدود الخدمة

- معلومات المسابقة لها مصدر وحالة تحقق وتوقيت مستقل. الادعاء المتداول عن «٣٠٠ فرصة يوميًا» غير مؤكد في سجل المشروع؛ لا يُعرض كحقيقة رسمية. راجع [RESEARCH.md](RESEARCH.md) قبل تحديث المعلومات.
- تحديث التصميم لا يغيّر تاريخ التحقق من المعلومات. يؤكد المدير المراجعة من الإجراء المخصص لذلك.
- عند تعذر الاتصال بالقاعدة، لا تُستبدل الأكواد بملف ثابت قد يعيد أكوادًا محذوفة. قد تعرض الجلسة المفتوحة آخر بيانات وصلتها حتى نجاح التحديث.
- الصور والفيديو تُضاف من الإدارة بروابط HTTPS أو مسارات ملفات محلية مسموحة. الفيديو يحتاج رابط ملف مباشر مثل MP4. الملفات المضافة داخل `public/` تحتاج نشرًا جديدًا، بينما تحديث رابط وسيط خارجي لا يحتاجه.
- لا توجد أدوات تتبع أو نوافذ إعلانية مدمجة. حدود الطلبات والبلاغات تستخدم معرّفات HMAC؛ عنوان الشبكة الخام لا يُخزن في جداول التطبيق. تعتمد آلية تحديد العميل على بروكسي Vercel؛ راجعها عند الانتقال لاستضافة أخرى.
- مدة التشغيل المقترحة للمبادرة منفصلة عن مدة المسابقة. لا يوجد حذف تلقائي للموقع أو موعد نهاية رسمي مستنتج؛ يمكن إيقاف استقبال الأكواد من الإدارة.

## المساهمة وحقوق الاستخدام

اقتراحات تحسين سهولة الاستخدام، وإمكانية الوصول، وتصحيح المصادر مرحب بها عبر Issues أو Pull Requests. احذف البيانات الشخصية من الصور والتقارير، ولا ترفق مفاتيح أو ملفات بيئة. قبل إرسال تعديل برمجي، شغّل فحص الأنواع والاختبارات والبناء.

خط Alexandria مرفق بترخيص [SIL Open Font License](public/OFL-Alexandria.txt). الأيقونات رسومات خاصة بالمشروع وليست شعار نسك. لا يوجد حاليًا ترخيص عام مستقل لكود المشروع؛ إتاحة المستودع للقراءة لا تمنح تلقائيًا ترخيصًا لإعادة استخدامه أو توزيعه.

## استيراد الأكواد وعداد الزيارات

من «إدارة الأكواد» اختر «استيراد ملف أكواد»، ثم اختر ملف TXT بترميز UTF-8، فيه كود واحد في كل سطر مثل `NG-Ab12Cd34`. الحد ٢٠٠٠ كود مختلف و٦٤ كيلوبايت للدفعة. تقدر تراجع عدد الأكواد قبل الضغط على «استيراد ونشر». الأكواد الموجودة تُتخطى بكل حالاتها، والاستيراد يبيّن عدد المنشور والمكرر.

شارة «جديد اليوم» تعرض الأكواد المنشورة التي أُضيفت خلال اليوم بتوقيت القاهرة. عداد الزيارات الإجمالي يبدأ بعد تفعيله ويحسب فتح الصفحة أو إعادة تحميلها، مع حد للطلبات. لا يقيس عدد الأشخاص الفريدين.

لتفعيل العداد على مشروع Supabase قائم، نفّذ [ترقية عداد الزيارات](supabase/migrations/20261106_site_visits.sql) في SQL Editor. الاستيراد وشارة اليوم يعملان باستخدام مخطط الأكواد الحالي.
