# مساعد أكواد نسك — الإدارة الديناميكية

تطبيق Next.js عربي يبدأ بالموبايل، بواجهة أكواد ودليل ومعلومات موثقة. البيانات المنشورة الآن في Supabase: حذف الكود أو تعديل المحتوى لا يحتاج بناء نسخة جديدة.

## التشغيل

```bash
npm ci
npm run dev
```

افتح `http://127.0.0.1:3000`، والإدارة في `/admin`. الاختبارات: `npm test`، الأنواع: `npm run typecheck`، البناء: `npm run build`.

## مشروع Supabase جديد

1. نفّذ `supabase/schema.sql` كاملًا مرة واحدة. ينشئ الجداول والدوال، وينقل ١٢١٦ كودًا من الملف الأصلي دون الادعاء بصلاحيتها، ويضيف محتوى الموقع الافتراضي.
2. أنشئ حساب مدير مؤكدًا من Supabase Auth، وعطّل التسجيل العام. يظل مزود الدخول بالبريد مفعّلًا.
3. أنشئ `.env.local` اعتمادًا على `.env.example`. المفتاح السري `SUPABASE_SERVICE_ROLE_KEY` للسيرفر فقط. يدعم هذا المتغير secret key الجديد أو service_role القديم.
4. ضع بريد المدير في `ADMIN_EMAILS` وسرًا عشوائيًا بطول ٣٢ حرفًا أو أكثر في `RATE_LIMIT_SECRET`، ثم أعد تشغيل التطبيق.
5. لا ترسل أسرارًا في الشات، ولا ترفع `.env.local` أو `.local-backups/` إلى مستودع أو أرشيف مشاركة.

## ترقية المشروع القديم

نفّذ `supabase/migrations/20261105_dynamic_admin.sql` مرة واحدة في SQL Editor. الملف قابل لإعادة التنفيذ دون إعادة إحياء الأكواد المحذوفة/المرفوضة أو الكتابة فوق إعداداتك. يحافظ على الصفوف السابقة ويستورد الأكواد غير الموجودة فقط. تم تأكيد تنفيذ هذه الترقية في مشروع صاحب الموقع.

## لوحة الإدارة

- **الأكواد**: كل الحالات، بحث وصفحات، إضافة ونشر كود، تعديل نص الكود، نشر أو رفض أو حذف.
- **المحذوفات**: الحذف قابل للاستعادة، ويمنع رجوع الكود تلقائيًا إذا أعاد زائر إرساله. الاستعادة إجراء صريح من المدير.
- **البلاغات**: حذف الكود وإغلاق بلاغاته في معاملة واحدة، أو إغلاق بلاغ فقط دون حذف الكود.
- **الإعدادات والمحتوى**: مفتاح النشر التلقائي (افتراضيًا true)، ومفتاح إيقاف استقبال الأكواد. النشر التلقائي يخص الإضافات الجديدة ولا ينشر المعلق سابقًا بأثر رجعي.
- تعديل الاسم والوصف والتعريف بالمطور والنصوص الرئيسية والروابط وتفاصيل الجوائز والتواريخ والتحديث المتداول وحالته ومصدره وصور الدليل والفيديو والأسئلة الشائعة.
- تغييرات الإعدادات تحتاج زر الحفظ. يوجد رقم إصدار لمنع جلسة قديمة من الكتابة فوق تعديل جلسة أخرى.
- تاريخ التحقق من معلومات المسابقة أو التحديث لا يُرفع تلقائيًا عند تعديل التصميم أو الروابط؛ زر مستقل يقر بأن المدير تحقق من المصدر الآن.

المحتوى في `site_settings.content`، مع `revision` للإعدادات و`codes_revision` للأكواد. الكتابة تمر عبر Next.js بعد التحقق من جلسة المدير والبريد المسموح. لا تمنح قاعدة البيانات أي وصول مباشر للزائر أو المستخدم العادي.

## ما يراه الزائر

- قاعدة البيانات وحدها تحدد الأكواد المنشورة. لا ندمج ملف الأكواد القديم عند كل طلب، وبالتالي لا يرجع المحذوف من مصدر ثابت.
- حفظ التقدم على جهاز المستخدم باستخدام localStorage، مع ترحيل v2 واستيراد/تصدير وتراجع. لا مزامنة بين الأجهزة دون ملف احتياطي.
- النشر التلقائي يظهر بوضوح في نص زر الإضافة. عند إغلاقه يرى المستخدم أن الإضافة تنتظر المراجعة.
- تحديث الصفحة يجلب البيانات الحالية. الصفحات المفتوحة تراجع التغييرات كل ٤٥ ثانية وعند العودة للتبويب. ETag يمنع إعادة تنزيل قائمة كاملة عندما لا توجد تغييرات.
- إذا تعطل Supabase لا نستبدل القائمة المنشورة بأكواد قد تكون حُذفت. جلسة مفتوحة قد تواصل عرض آخر بيانات وصلتها حتى نجاح التحديث؛ الزائر الجديد يرى رسالة تعذر الاتصال.
- متابعة النسخ والاستخدام ليست عدد فرص السحب ولا تحققًا من صلاحية الكود في نسك.

## الصور والفيديو

أضف من الإدارة روابط الصور الحقيقية بعد إخفاء البيانات الشخصية. الروابط تقبل https أو مسار ملفات داخل الموقع. صورة جديدة من تخزين وسائط خارجي لا تحتاج إعادة نشر؛ إضافة ملف داخل public تتطلب رفعه إلى الاستضافة. الفيديو يحتاج رابط ملف مباشر (مثل mp4)، وليس رابط صفحة YouTube. لا تشغيل تلقائي.

## حماية الطلبات والبيانات

التحقق من صيغة الكود وتفرده يتم على السيرفر والقاعدة. حدود الإرسال RPC ذرية، ومفاتيح الإدارة لا تدخل كود المتصفح. على Vercel نستخدم عنوان البروكسي الموثوق لتوليد HMAC؛ عنوان الشبكة الخام غير مخزن في جداولنا. على مزود استضافة مختلف يجب ضبط مصدر عنوان العميل الموثوق. سجل البلاغ يحفظ HMAC لمنع البلاغ المكرر؛ راجع سياسة الاحتفاظ به عند انتهاء المبادرة.

ملفات `data/codes.json` و`data/legacy-codes.json` نسخ أصلية للمراجعة/الترحيل فقط؛ الأولى لا تُستخدم كمصدر يعيد أكوادًا حُذفت من القاعدة. نقل التقدم بين origin مختلفين يحتاج تصديرًا واستيرادًا.

## المعاينة والاختبارات

`npm run preview:html` ينتج `../nusuk_first_version.html`: لقطة مستقلة من الأكواد والمحتوى المنشور وقت التوليد إذا كان Supabase مضبوطًا. الملف ليس لوحة إدارة أو مصدرًا حيًا؛ التعديلات اللاحقة تُراجع من الموقع المتصل.

`node scripts/check-dynamic-data.mjs` اختبار متصل قابل للعكس، يُشغّل على مشروع التطوير غير المنشور فقط. يبدّل النشر التلقائي مؤقتًا، وينشئ أكواد QA فريدة، ويختبر النشر/المراجعة/الحذف/الاستعادة/إغلاق البلاغات/ETag، ثم ينظف صفوفه ويعيد السياسة السابقة. يحتاج سيرفرًا محليًا يعمل ومتغيرات `.env.local`. لا تشغله على موقع يستقبل مستخدمين فعليين أثناء الاختبار.

## النشر والنهاية

أضف متغيرات البيئة نفسها إلى Vercel واضبط `NEXT_PUBLIC_SITE_URL` للرابط النهائي. ملف `.env.local` لا يُرفع. اختيار خطة الاستضافة يخضع لشروطها والاستخدام الفعلي. تعديل الكود أو الشكل يحتاج إصدارًا؛ إدارة الأكواد والمحتوى من اللوحة لا تحتاجه.

مدة الأداة المقترحة ٥٠ يومًا لا تثبت مدة المسابقة. لا يوجد موعد نهاية رسمي مستنتج ولا حذف تلقائي. يمكن إغلاق استقبال الأكواد من الإدارة. راجع RESEARCH.md للمصادر وحدود التحقق.

## hydration والخط

التحذير المبلغ عنه كان خاصية location مضافة إلى body خارج كود المشروع. عولج على body فقط بـsuppressHydrationWarning، دون إخفاء اختلافات العناصر الداخلية. قد تظل إضافة المتصفح نفسها تضيف الخاصية؛ هذه الخاصية ليست وظيفة داخل الموقع.

خط Alexandria موروث من الملف الأصلي بترخيص SIL OFL المرفق في public/OFL-Alexandria.txt. الأيقونات رسومات خاصة بالمشروع وليست شعار نسك. لا توجد أدوات تتبع أو نوافذ ترويجية.
